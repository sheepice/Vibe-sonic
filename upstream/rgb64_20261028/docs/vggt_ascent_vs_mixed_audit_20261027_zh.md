# 2026-10-27：纯上楼与混合楼梯 VGGT 蒸馏实验核对

本报告对照两轮运行保存的配置、源码快照、checkpoint、训练状态和已有录像。原始分工依据 `current_hiking_gaussgym_vibe_architecture_20261024_zh.md`。这里的“昨天”指 `vggt_ascent_*_20261026`，“今天”指 `vggt_stairs_*_20261027`。

结论：**相同 variant 的参数化网络主干和损失系数相同，但视觉输入、蒸馏位置对齐、任务分配和每轮优化预算有实质差别。现有对比不能把上楼打脚恶化全部归因于数据配比或训练轮数。**

最需要优先检查的实现问题是：相机从 112×64 改成 112×63 后，Theia 丢掉底部 15 行，而 VGGT 教师仍使用全图。实际冻结模型的 CPU 扰动实验已确认前者；代码中的全图重采样确认了教师与学生的空间采样位置不一致。它对控制性能的因果贡献还没有消融证据。

## 1. 网络到底是否相同

| 项目 | 核对结果 |
|---|---|
| Actor 定义 `vggt_distill/model.py` | 两轮源码哈希相同 |
| VGGT 教师 `teacher.py` | 两轮源码哈希相同，教师权重和版本相同 |
| 同 variant 的 Actor / Critic state_dict | 所有 tensor key 与形状相同 |
| middle 参数量 | 两轮均 16,777,271；可训练 2,361,789 |
| hierarchical 参数量 | 两轮均 19,076,919；可训练 4,661,437 |
| SONIC / Theia | 均冻结，无独立几何分支，无新增时序记忆 |
| 初始控制主干与 Critic 参数摘要 | 两轮相同：`1e7de540…cdd0706` |
| 初始二阶段模型 | 均从 `20261016_vibe_rgb_stairs_only/model_14999.pt` 初始化 |
| 学习率 / PPO / DAgger | 1e-4 固定学习率、3 epochs、DAgger 0.8 均相同 |
| 蒸馏权重 | 空间 0.3、关系 0.05、进度 0.03 均相同 |

初始摘要排除了对齐头；对齐头的源码、固定初始化种子和形状也分别一致。hierarchical 今天中途从本轮 `model_700.pt` 恢复，核对首次初始化时使用了恢复前归档，而不是把恢复时权重摘要误当作首次初始化摘要。

**今天是重新开启的二阶段训练，并没有从昨天训练好的 900 轮策略继续学习。** 因此目前的现象不是已证明“给昨天的好模型加了下楼数据后发生遗忘”，而是两条从同一基础模型出发的不同学习轨迹。

middle 在学生第二个空间块对齐教师第 23 层；hierarchical 三个块分别对齐 11/17/23 层。这种 variant 间区别昨天、今天都有，不能把 middle 与 hierarchical 直接当成数据配比消融。

项目源码快照共有 262 个 Python 文件参与比较，只有以下 7 个变化：`vggt_distill/{task,collection,algorithm,train,audit,scenes,evaluate}.py`。其中训练变化是任务路由、上下沿标签、张量广播及记录；场景与评估改动也需要在录像比较时控制。旧快照未覆盖所有 vendor 源码，不能据此声称整个软件环境逐字节相同。

## 2. 新发现：63 像素高造成视觉裁失和空间对齐差异

### 2.1 追溯：为什么从 64 改回 63

用户追问后进一步回查历史说明，发现这不是此前没有记录过的编码器特性：昨天的 `vibe_vggt_distillation_ascent_20261026_zh.md` 第 74 行已明确说明，使用 112×64 是为了得到完整的 4×7 patch，避免底部条带被丢弃。今天的 `vibe_vggt_stairs_retrain_20261027_zh.md` 第 69 行则写着“本轮恢复原RGB分辨率112×63，因此学生patch网格为3×7”。

因此，配置变化的记录理由是恢复原几何分支路线的 RGB 尺寸；恢复数据与任务分配本身不需要改回这个尺寸。此次配置恢复没有保留昨天已有明确理由的完整 patch 输入，是一次配置回退失误。前文“新发现”指本次审计重新确认当前运行存在这个问题，不能理解为昨天尚不知道 63 高会丢弃底部。图像没有在数据文件里被删除，而是在 patch 卷积中未被覆盖；检查网络形状匹配和训练能运行不足以发现这个语义问题。

### 2.2 实际影响与 CPU 验证

实际视觉路径是 RGB → 归一化 → Theia；中间没有 resize 到 224，也没有补齐到 16 的倍数。实际模型的 patch projection 为：

`Conv2d(3, 192, kernel_size=(16,16), stride=(16,16), padding=0)`。

| 项目 | 昨天 | 今天 |
|---|---:|---:|
| RGB 宽×高 | 112×64 | 112×63 |
| patch 网格 | 4×7 | 3×7 |
| patch 数量，不含 CLS | 28 | 21 |
| 编码覆盖的像素行，0 起算 | 0–63 | 0–47 |
| 底部未进入编码的像素行 | 无 | 48–62，共 15 行 |

CPU 验证使用同一冻结模型、同一张量，仅将指定像素行从 0 改成 1：

| 扰动 | patch 输出最大绝对变化 | CLS 输出最大绝对变化 |
|---|---:|---:|
| 63 高，改底部 48–62 行 | **0** | **0** |
| 63 高，改上部 0–47 行，正对照 | 2.25646 | 0.04261 |
| 64 高，改底部 48–63 行 | 1.30724 | 0.02025 |

这证明 63 高的底部像素没有进入当前视觉特征。画面底部是否恰好包含某一步的关键台阶沿，需要逐帧投影分析，不能仅凭这个实验断言；但针对近脚障碍理解，这是需要排除的重大输入差异。

同时，`GeometryTeacher.__call__` 把**整张** RGB resize 到 240×416，得到 15×26 的教师 patch，再按整个画面插值到 3×7。学生却只有上部 48 行对应的 3×7 patch。二者都叫“3×7”，并不表示采样位置相同：

| 从上到下的归一化纵向采样中心 | 学生 | 教师重采样网格 |
|---|---|---|
| 64 高 / 4 行 | 0.125、0.375、0.625、0.875 | 0.125、0.375、0.625、0.875 |
| 63 高 / 3 行 | 0.127、0.381、0.635 | 0.167、0.500、0.833 |

这里讨论 patch 采样位置；Transformer 特征有全局上下文，不能把上述中心当成特征的完整感受野。尽管如此，全图到三行的教师采样与截去底部的学生采样存在明确的空间对应偏差。

这不是“少 1 像素所以影响很小”。参数尺寸不变也不能排除它。蒸馏损失按 patch 求均值，因此也不能把少 25% token 直接解释成损失权重少 25%。

原几何分支文档本来就使用 112×63，它能训练出较好效果，说明 63 高并不等价于无法学习。但那一路没有本次逐 patch 的 VGGT 全图对齐，且存在几何预训练和时序记忆，不能据此排除这里的对应偏差。

## 3. 数据源相同，但实际用途与任务分配不同

两轮使用同一 `data/full_four_gpu_20261021`，四个分片合计 5,799 条 GRAIL 配对地形记录。平地来源内部权重也相同：LAFAN 0.3、100style 0.2、SONIC 0.4、real_pico 0.1。

昨天虽然加载了 bank，但 paired 环境数量为 0，并移除了配对 GRAIL 地形。今天恢复了这些原有数据的 PPO 使用。**不是今天少加载了某个数据文件，而是训练任务的使用方式变化。**

下表是总环境占比；在线地形行按 reset 概率折算，不是逐时刻固定数量：

| 用途 | 昨天占比 | 今天占比 | 昨天每卡数量 | 今天每卡名义数量 |
|---|---:|---:|---:|---:|
| 纯上楼在线 PPO | 70% | 17.5% | 5600 | 1050 |
| 纯下楼在线 PPO | 0 | 12.5% | 0 | 750 |
| 上下楼组合在线 PPO | 0 | 12.5% | 0 | 750 |
| 在线平地 PPO | 0 | 7.5% | 0 | 450 |
| GRAIL 配对 PPO | 0 | 20% | 0 | 1200 |
| 规划器平地 DAgger | 15% | 15% | 1200 | 900 |
| 混合动作平地 DAgger | 15% | 15% | 1200 | 900 |
| 合计 | 100% | 100% | 8000 | 6000 |

今天在线 50% 内部按上楼/下楼/上下楼/平地 = 35/25/25/15 采样。上下楼组合也提供上楼经验，部分配对 GRAIL 也包含楼梯，所以 **5600/1050 ≈ 5.33 不能当作全部上楼经验的精确缩减倍数，更不能直接换算收敛所需轮数。**

需要修正先前“平地占比没有增加”的表述：固定的两组平地 DAgger 合计仍是 30%，但今天又有名义 7.5% 在线平地，总计名义 37.5%。实际快照约 38.5%–39.0%；这仍不包括 GRAIL 配对动作中的平地片段。环境比例也不等于优化器梯度权重，因为 DAgger 使用单独采样的监督损失。

## 4. 规则楼梯仍在；速度也一直都有，但分布变了

两轮均调用同一 `normal_tiles`：每种方向 11 个难度级、3 种变体；variant 0 为等高等深规则楼梯，variant 1/2 为不规则楼梯。每段 4–8 级，踏面 28–40 cm，高度截断在 2.5–25 cm。昨天把在线下楼/上下楼槽位替换为上楼拷贝，今天恢复四种方向/平地。

所以，**今天并非漏掉仿真生成的规则楼梯，也不是昨天只训练单一速度**。两轮走路速度流都有 0.25、0.4、0.5、0.7 m/s，且含小幅指令扰动。

速度的实际差别是：昨天纯上楼明确排除 0 速；今天在线任务恢复 6% 的停止指令 reset 概率。停止状态没有走到终点的提前成功退出，往往驻留更久。四卡状态快照中的在线 0 速占比为 middle 17.08%、hierarchical 16.26%，高于 6% 的 reset 概率。

同一快照，每卡平均“纯上楼且非零速度”约为 middle 715.5、hierarchical 750.75 个；昨天全部 5600 个纯上楼环境都非零速度。这些是某时刻的占用量，不是训练全程平均，也没有包含组合路线的上楼段。慢速、组合路线也可能因 episode 较长获得更高的逐步样本占比，不能只看 reset 权重就认定各种速度均衡。

出生位置扰动也略有变化：昨天 x±0.35 m、y±0.25 m；今天基础 profile sampler 为 x±0.30 m、y±0.35 m。相同 RNG 种子不能让两套采样路径产生逐条相同的轨迹。

## 5. 同样一轮，今天训练预算更小

每轮 rollout 均为 24 步，3 个 PPO epochs，但环境数下降会自动减少 minibatch 数：

| 每卡、每轮 | 昨天 | 今天 |
|---|---:|---:|
| 总物理环境 | 8000 | 6000 |
| PPO 环境 | 5600 | 4200 |
| 新 PPO transition | 134400 | 100800 |
| 每个 epoch 的 minibatch | 132 | 99 |
| 实际 minibatch 大小 | 1018 | 1018 |
| Adam 更新次数 | 396 | 297 |
| 蒸馏辅助 minibatch | 99 | 75 |
| 每轮新教师图像，稳定阶段 | 64 | 64 |

今天每轮 PPO 样本和 Adam 更新次数均少 25%。例如按轮数近似计算，今天 middle 1100 轮约 326,700 次 Adam 更新，昨天 900 轮约 356,400 次；checkpoint 编号存在首轮编号差异，不影响这个数量级判断。今天轮数更大不代表优化预算更多。

蒸馏只从 `ppo_online` 均匀抽图，不从配对 GRAIL 或 DAgger 环境抽图；没有按方向、非零速度、靠近台阶沿的状态分层。昨天每轮 64 张都来自移动上楼任务，今天这 64 张分给所有在线任务，还包含停止状态。

按本次并发状态快照估计，每轮新教师图像中：纯上楼约 19–20 张，纯上楼且非零速度约 15–16 张。它们是期望值，不是记录出的逐张计数；组合路线也提供上楼图片。教师缓存仍为 512 张，辅助 batch 仍为 16，今天单轮辅助 batch 从 99 降到 75。

因此恢复大任务范围后，教师覆盖和针对上楼的监督次数没有同步增加。这是明确的预算变化；不能据此断言 VGGT 本身无效。

## 6. 防打脚奖励没改，但在联合训练中的作用分布变了

奖励代码和配置相同，包括脚撞立面 -0.5、小腿撞击 -0.8、摆腿路径 -0.35、支撑余量 -0.4、滑动 -0.4、硬着陆 -0.15、Hiking 边缘代价 -0.35。

`FootholdGuidance.ids` 只选择 `ppo_online`。因此今天新增的 20% 配对 GRAIL PPO 并不直接获得这套在线楼梯质量奖励。昨天 PPO 5600 个环境全部是上楼；今天 PPO 4200 个中 1200 个是配对跟踪，占 PPO 的 28.57%。名义纯上楼只占 PPO 的 25%，其余还包括下楼、组合、在线平地。

PPO 在每卡整个 rollout 上共同标准化 advantage，并随机混合 minibatch，没有按任务单独标准化或维持上楼的独立更新配额。DAgger 仍每个优化步骤采样 256 个平地状态、系数 0.8。上楼经验下降后，即使系数不变，联合学习中各目标的相对作用仍然改变。

这支持“上楼防打脚目标被其他任务分摊”的解释，但没有测量过任务之间的梯度余弦、梯度范数比例，不能把“配对数据或平地梯度压过了上楼”写成已验证事实。日志 `Distill/shared_gradient_norm` 是首次连通性审计缓存，不是逐轮实时梯度，不适合用来证明这一点。

关系辅助标签也变了：昨天找前方上升台阶沿，今天允许上升和下降边沿。关系头形状与权重没有变化，但学习问题从单方向扩展为双方向。这项改动符合下楼目标；同时它说明损失形式相同不代表标签分布相同。

## 7. 课程按轮数升级，没有补偿上楼经验减少

两轮课程都是每 150 次 policy update 扩大一个可采样级别。规则楼梯的理论高度上界随课程约为：

| update 区间 | 最高 level | 对应最高理论台阶高度 |
|---|---:|---:|
| 900–1049 | 7 | 18.9 cm |
| 1050–1199 | 8 | 21.0 cm |
| 1200–1349 | 9 | 23.1 cm |
| ≥1350 | 10 | 25 cm，上限裁剪 |

每个具体随机生成地形不一定达到理论上界，难度级别在已开放范围内均匀抽样。今天录像使用的 middle 1100 刚进入覆盖 20 cm 附近的级别，hierarchical 1000 尚未进入；高台阶曝光有限，同时每个难度阶段获得的纯上楼练习少于昨天。不过，昨天 900 轮同样尚未开放该级别，却在这次 20 cm 测试中脚撞更少，因此“高台阶练得还不够”不能单独解释新旧差异。30 cm 超出在线生成器上限；配对 GRAIL 的范围需另行统计，不能把 25 cm 说成全部训练数据的绝对上限。

不能按 `900×5.33≈4800` 得出“今天训练 4800 轮就必然追平”：组合路线贡献、不同高度曝光、视觉输入、优化预算与任务共享都不满足这个换算前提。

## 8. 录像定量核对：用户观察有依据

使用已有 20 cm、0.4 m/s、6 级规则楼梯录像。新旧初始 root、关节、spawn、命令、地形逐项相同。旧新结束判据有差异，所以接触对比截取相同 root 局部 x ∈ [0.9,3.85] 的楼梯区间，避免终点多走几步影响计数。

| 模型 | checkpoint | 脚撞立面事件 | 脚撞冲量 N·s | 小腿撞击事件 |
|---|---:|---:|---:|---:|
| 昨天 middle | 900 | 0 | 0.00 | 3 |
| 今天 middle | 1100 | 8 | 69.64 | 1 |
| 昨天 hierarchical | 900 | 2 | 11.71 | 1 |
| 今天 hierarchical | 1000 | 8 | 55.59 | 1 |

事件按接触力超过 15 N 的上升沿计数，可能同一台阶重复接触；不是“撞了几个不同台阶”。这些模型在该例均能通过。旧 middle 仍有小腿接触，不应描述成完全零碰撞。今天脚撞立面明显恶化，同时小腿指标未必恶化；成功率不足以代表动作质量。

这组结果只证明相同已录场景中的差异。每个模型只取一个 seed/phase，不能外推成总体碰撞率，也不能分离数据分配和视觉变化各自的因果作用。

## 9. 为什么旧几何分支用这套配比能较好，而当前 VGGT 不一定立刻复现

原架构文档记录的是含几何预训练、LSTM 时序状态、独立几何监督优化器的路线，展示 checkpoint 为 5750。几何网络预训练计划 30,000 次更新，PPO 不反传几何主干；当前 VGGT 路线使用单帧共享空间块，与 PPO、DAgger 在同一策略优化器上共同学习。

因此相同 50/20/15/15 环境分工在两种表征和优化方式下未必得到相同的学习速度。原成功结果说明这套数据值得保留，不能据此认定当前 1000 多轮表现差一定是数据错了，也不能据此证明独立几何分支可以被无损替换。

## 10. 建议的排查顺序

1. **先统一视觉输入和师生采样位置。** 以两侧一致的 112×64 / 4×7 作为清晰基线，或设计明确一致的 resize/pad/crop 方案。不能仅把已有 63 高策略评估时改成 64 高，就宣称训练问题被修复。
2. **先保留原 50/20/15/15，检验视觉差异。** 在同一 variant、6000 环境、相同初始化/种子/优化预算下对照 63 与 64 的混合训练，避免同时改配比、奖励和视觉后无法归因。
3. **再隔离任务分配。** 严格的 2×2 对照为纯上楼/混合任务 × 63/64 输入，均固定 6000 环境。已有旧上楼 8000 环境结果只是参考，不能冒充严格对照。纯上楼用于诊断；最终训练目标仍包括上下楼与多个速度。
4. **按实际移动楼梯曝光分配监督。** 统计方向×速度×难度的 transition 与近台阶沿图像量；可以让教师按这些条件分层采样，把静止、平地和已通过楼梯的冗余图像控制在适当份额，再评估是否需要改变环境配比。不要直接把所有平地保持数据删除。
5. **固定评估集决定是否继续加轮数。** 用相同 20 cm / 25 cm，上楼、下楼、组合路线，0.25 / 0.4 / 0.7 m/s，多初始相位/种子，分别报告通过率、脚/小腿撞击冲量、悬边、速度误差。将 30 cm 单列为在线生成器范围外测试。

目前更有依据的判断是：**上楼练习和上楼蒸馏监督减少，是确定事实；底部视觉裁失和师生采样错位，是需要优先排除的确定实现差异；多任务干扰是合理假设；“继续多跑一些轮数就会解决”没有足够证据。**
